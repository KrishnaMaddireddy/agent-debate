What changed (rev 14) — the PRD debate engine replaces the panel; zero dependencies; one engine everywhere
- Redesign. The rev ≤13 panel/compare app (agent-debate.jsx, local/*.js, Express, esbuild, React) moves to
  legacy/. The new app runs the PRD protocol:
  - reading → independent answers with claims → code audit → participation gate → code-computed diff;
  - then rounds of critique and rebuttal, a post-debate diff and a joint memo.
  The console follows Model Bridge's layout: a Run configuration card, an "Intent, as read" card, a
  live feed, and panels computed by code. docs/DESIGN.md is the contract.
- Zero runtime dependencies: node:http, vanilla ES modules served as-is, node:test. There is no
  npm install and no node_modules; the device VM can run the tests.
- app/core (browser-safe): engine, prompts, audit, metrics, record, json, text, calc, files,
  tools-protocol, mock-models. The same files run in the server, the console (imported directly from
  /core/*.js) and the claude.ai page. A test asserts byte-identity for every engine function in the
  page.
- Phase 0 intent reading.
  - The reading is shared with every later prompt, the memo writer's included.
  - If the chosen reader fails, the next analyst on a different model reads it once. The fallback is
    recorded.
- Phase 1.
  - Concurrent and independent: identical user prompts, and nobody sees anybody.
  - Each claim carries a basis (quote | arithmetic | tool | reasoning | knowledge), evidence and a
    load-bearing flag.
  - Audit statuses: verified, verified_normalised, verified_elided, fabricated_quote, too_short;
    arithmetic miscomputed / unsourced_operands; tool missing_tool_result / failed_tool /
    tool_mismatch.
- Guards.
  - Participation gate: empty, failed and template-copying analysts are absent, not disagreeing.
  - Template-copy detection in every shape.
  - One JSON repair.
  - Reasoning-channel recovery, now noted on the answer.
  - Chain-of-thought memo re-asked, then labelled.
- Critique.
  - The agenda: every claim of the others with no counterpart of the critic's own must get a verdict.
  - Root causes: evidence / interpretation / values, tallied by code.
- Rebuttal.
  - Identity-anchored: the analyst's own current answer plus only what was said to it.
  - withdrawn_claims and new_claims are applied and audited.
  - Rounds re-critique the current answers, and auto-stop when nobody moves.
- Diff.
  - Claim clustering is polarity-aware (opposite claims never merge) and requires numbers to agree.
  - Also computed: pairwise overlap, position similarity, item consensus, verdict tally, movement and
    "towards".
  - A red flag is raised when agreement rises while grounding falls.
- The judging lens (persona) now reaches every phase: answer, critique, rebuttal and memo.
- Runs.
  - Events are appended to local/runs/<id>.jsonl as they happen and replayed over SSE.
  - On finish the run also writes <id>.json (record), .md (report), .meta.json and files/.
  - Rev ≤13 runs (panel-*, compare-*) are listed as legacy with their reports.
- Server.
  - Loopback only, a Host allowlist (DNS rebinding), an Origin check on writes.
  - Keys are never returned; providers are opt-in; unlisted models are refused before any call.
  - Stop aborts in-flight calls (AbortSignal, including the Claude CLI process).
- Adapters: learned temperature fix, max_completion_tokens, reasoning retry at twice the ceiling,
  thinking dialect by base URL, and timeouts that follow the ceiling.
- The Claude CLI seat keeps its isolation (empty temp dir, tools off, preamble, no ANTHROPIC_API_KEY).
- Mock models: every behaviour (mock-1…mock-svg) is always offered, whatever an older providers.json
  listed.
- claude.ai page: build/artifact.js links the modules into dist/agent-debate.html.
  - Claude tiers are reached through the sample capability.
  - Reports are saved through the downloads capability.
- Removed from the generic app: the markets plugin (moved to legacy/) and the Alpha Vantage MCP
  example. plugins/example-fact-check (a Crossref DOI lookup and a Wayback snapshot, both keyless)
  is the new worked example.
- app/server/tools-check.mjs: checks every tool in the catalog, including plugins and MCP.
- Live check (DeepSeek deepseek-chat ×2, 1 round, one document; about 8 calls). Every phase ran and the
  memo was clean, but it exposed four defects. All four are fixed, with regression tests:
  - Critics copied whole agenda rows as the claim reference ("B:c4 — Denver had 800 …"). normRef
    rejected them, so every verdict was dropped (0 verdicts, 7–8 claims unargued). A reference at the
    start of longer text now counts. After the fix: 14 verdicts, none unargued.
  - The arithmetic audit read "1200 - 800; 1200 - 300" as one expression (unparseable) and missed a
    result written as a word ("three cities", marked miscomputed). Now each computation is checked and
    number words are read.
  - Quotes shorter than 20 characters were refused even when they carried the figure ("Denver 800").
    Short quotes with a number are now checked verbatim.
  - Items annotated with their rank ("Austin — first") never matched "Austin", so identical picks
    showed as 0% item agreement. The item key is now the name alone, and the schema asks for the name
    only.

  one final turn asking for the answer, instead of being recorded "absent" (a 104 s Kimi run produced nothing).
